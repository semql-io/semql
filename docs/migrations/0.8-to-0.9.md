# Migrating from SemQL 0.8 to 0.9

The eight packages remain versioned together. Upgrade them together; sibling
requirements are `>=0.9.0,<0.10`. Version 0.9.0 is the next release candidate;
opening its pull request does not publish the distributions.

## Query-budget admission

`QueryBudget(max_rows_scanned=...)` now rejects unknown-size referenced cubes
by default. If your application intentionally admits uncertainty, set
`unknown_cost_policy="allow"`. The known size-hint subtotal must still fit:
allowing unknown cost does not bypass an already-exceeded known subtotal.

`CostEstimate.cubes_unknown` retains each unknown cube's identity. The
`rows_scanned_unknown` summary is derived from those identities. Persisted
estimates with only `rows_scanned_unknown=True` must be regenerated; they cannot
establish how many cubes were referenced. Duplicate unknown identities and
known/unknown overlap reject. `max_cubes` counts both sets.

`estimate_cost(..., views=catalog.views)` shares reference resolution with the
compiler. It accounts for resolvable referenced dependencies, including derived
operands and nested semi-join requests. These remain declared size-hint subtotals,
not measurements or predictions of physical scan work, selectivity, join fanout,
execution time, or memory consumption. Query validity must still be checked by
compilation; admission is not authorization.

## Prompt-budget results

Replace reads of `BudgetResult.estimated_tokens` with `token_count`. Inspect
`count_source` (`heuristic` or `callback`) and always check `fits` before sending
a budgeted prompt. `was_truncated` means optional content was removed, not that
the result fits. Required/unrecognized content can remain oversized with
`fits=False`; this includes a zero budget. There is no implicit empty-prompt
fallback.

```python
from semql_prompt import PromptBudget

result = PromptBudget(max_tokens=4096).apply(prompt, count_tokens=model_token_counter)
if not result.fits:
    # The application decides whether to reject or choose another context budget.
    raise ValueError("Required prompt content does not fit")
text = result.text
```

`count_tokens` is an optional caller-supplied callable from text to a nonnegative
integer. Omitting it uses the labeled character-based heuristic, not a
model-specific guarantee. Recognized rendered cube blocks and optional catalog
sections can be trimmed; unrelated instruction/view headings are preserved.

## Explanations and repair diagnostics

`render_analysis(compiled.analysis)` renders the existing artifact graph without
re-resolution, SQL parsing, or catalog access. It omits catalog/source names,
private bindings, policy inputs, and raw SQL; labels are bounded and escaped.
Unknown physical strategy or graph references are reported as unestablished or
unavailable. Catalog assumptions are not runtime verification; the renderer does
not infer runtime evidence from a descriptor's verification string.

`Catalog.explain(query)` remains a privileged logical-plan view, not this safe
renderer. Neither explanation proves data completeness or live key uniqueness.

Public diagnostics add a bounded `category`, generic `repair_hint`, and optional
structural `location` when provenance is available. Locations identify a query
section and, where available, an item/operand index; absent locations must not be
invented by consumers. Existing exception subclasses remain catchable. Use
`to_public_payload()` externally, not sensitive internal payloads. Provider-facing
query-schema adapters and caller-owned fallback/authentication policies remain
unchanged.
