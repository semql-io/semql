# Migrating from SemQL 0.7 to 0.8

SemQL 0.8 changes several contracts intentionally. Review the items below before
upgrading the lockstep SemQL packages; do not update a stored executable's version
number by hand. Recompile stored executable plans with the 0.8 compiler.

## `enrich_all` requires analysis and returns `EnrichedResult`

Enrichment now resolves lookup inputs from the compiled semantic outputs, including
SQL aliases. Pass the analysis from the execution artifact and read rows and updated
analysis from the returned value:

```python
from semql import ResolutionContext, enrich_all

# Convert tuple rows by their unchanged output-column names.
rows = [dict(zip(result.columns, row, strict=True)) for row in result.rows]
output = enrich_all(
    rows,
    catalog,
    ResolutionContext(viewer=verified_viewer),
    analysis=result.analysis,
)
rows = output.rows
analysis = output.analysis
```

`analysis` is required; without semantic output mappings lookup identity cannot be
established. Original result keys, references, and grain are preserved. Added
fields carry enrichment provenance in the returned analysis. Enrichment returns
copied rows; avoid enriching against guessed field names or dropping the returned
analysis.

## Federated executable version 3

Federated executables are version 3. Older serialized plans are not upgraded by
editing their `version` field: they may lack required analysis and executable
binding contracts. Recompile the original `SemanticQuery` against the current
catalog, then execute the new plan. Callers that persist only a compiled artifact
must retain a way to regenerate it from the query/catalog definition.

The engine validates supported artifact versions and required parameter bindings
before cache lookup or adapter access. A mismatch is a contract error, not a signal
to execute a best-effort legacy plan.

## Comparison: unknown is not equivalent

`compare_analysis` can return `equivalent`, `different`, or `not_established`.
A missing proof is not a negative comparison and must not be treated as
`equivalent`. Expression comparison does not certify matching result populations;
use `scope="result"` when the intended question is whether result contracts match.

Result equivalence requires sufficient evidence for catalog snapshot identity and
request-bound policy context. The host owns catalog namespace/revision. For
scoped requests, supply the complete private contexts keyed by the analyses'
semantic binding slots, or independently establish equality and attest it with
`bound_context_equal=True`. Do not infer that two callers have the same authorized
cohort merely because they share a catalog revision. Comparison output does not
expose binding values and does not prove equality of live database contents.

## Symmetric federation uses observed qualifying facts

Symmetric multi-fact aggregation includes entity keys observed in qualifying fact
rows. Keys present in one fact, including rows whose measure values are all NULL,
remain represented. A dimension-only entity absent from every qualifying fact is
not implicitly added to the result. If an application needs a full dimension
universe, express that population explicitly in the query/application contract;
do not rely on the previous implicit full-dimension behavior.

## Duplicate semantic projections reject

Selecting the same semantic field more than once as independent projections now
rejects rather than creating ambiguous semantic outputs. To display a metric in
multiple presentation positions, project it once and reuse that output in the
presentation layer. A distinct output alias remains available for supported alias
use; aliases do not make repeated semantic projections into separate metrics.

## Public diagnostics are not internal error dumps

For API responses and routine external logging, use `error.to_public_payload()`.
It emits allowlisted diagnostic fields and does not copy arbitrary exception text,
SQL, bound parameter values, or repair arguments. `to_payload()` remains a
lossless internal serialization and can contain sensitive information; reserve it
for trusted internal repair/round-trip paths. Do not expose compiled artifact
`model_dump()` output as a diagnostic response because it can include parameters.

Additive APIs in the current release do not change this 0.7-to-0.8 migration
contract: `Diagnostic` may include bounded categories and repair hints, with an
optional source `location` (section, index, and optional operand index) only when
the compiler has provenance. For safe analysis summaries, use the exported
`render_analysis(analysis)` renderer rather than `Catalog.explain(query)`, which
remains the privileged resolving/logical-plan view. The renderer works from
analysis alone and omits private bindings and predicates.

Retain provider-facing `SafeSemanticQuery` adapters and their existing auth,
authorization, admission, and caller-specific policy. This library migration does
not require replacing provider schemas or moving authentication into SemQL.

## Execution, caching, and stream ownership

The caller remains responsible for supplying a trusted `AuthContext` derived from
its authenticated request and the policy context used during compilation. A
client-provided viewer ID or role list is not proof of identity. If a synchronous
`Engine` is shared across tenants or viewers and caching is enabled, pass a stable
trust-boundary `cache_namespace` to every `run` call (or isolate engines). Namespace
partitioning is an application responsibility; the cache is not distributed.

When consuming `Engine.iter_rows`, close the returned iterator in `finally` if
iteration may stop early. Iterator analysis and validation evidence belong to that
stream. Close caller-owned database connections after the engine/adapters stop
using them. `AsyncEngine` does not provide the synchronous result cache.

## Run the installed-package recipe

The repository demo is intentionally offline. To run it with installed packages,
not editable workspace imports, create a clean environment and install the
lockstep distribution plus DuckDB:

```sh
python3 -m venv /tmp/semql-0.8-demo
/tmp/semql-0.8-demo/bin/python -m pip install --upgrade pip
/tmp/semql-0.8-demo/bin/python -m pip install 'semql==0.8.0' 'semql-engine==0.8.0' duckdb
/tmp/semql-0.8-demo/bin/python demos/integration_recipes.py
```

Run those commands from the repository root to supply the demo script path. The
Python executable is the new environment's interpreter; the packages are installed
from the package index, not via workspace `uv run` or editable installs. Successful
execution prints each recipe heading and ends with `all integration recipes passed`.
